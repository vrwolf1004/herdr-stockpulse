## 개선 제안 (2026-10-23)

### 1. 종목 하나가 느리면 전체 갱신이 기다림

- **현상**: `dashboard()` 는 `pool.map` 으로 모든 종목의 결과를 받은 뒤에야 화면을 그린다(`src/panel.py:83-85`). 종목 하나의 조회는 Yahoo 와 iTick 대체 조회를 합쳐 제한 시간 10초씩(`src/quotes.py:22`), 최대 20초까지 걸릴 수 있다. 병렬 개수는 8개다(`src/panel.py:24`). 주석은 "느린 종목 하나가 갱신 주기를 넘기지 않게 한다"고 적었지만, 종목이 많으면 한 바퀴가 60초를 넘을 수 있다. 다음 갱신은 시작 시각 기준으로 잡히므로 그 사이 화면이 낡는다(`src/panel.py:143-157`).
- **개선안**: 종목마다 마감 시간을 두어, 기한 안에 못 받은 종목은 이전 값과 "지연" 표시로 두고 나머지를 그린다. 또는 주석과 실제 동작을 맞춘다.
- **범위**: `src/panel.py` (`dashboard`, 갱신 루프), `src/quotes.py` (제한 시간 상수)
- **확인**: 종목 20개와 응답이 느린 종목 하나를 가정해 한 바퀴 시간을 계산하거나 잰다. 실행하지 않았다(확인 필요).
→ 완료: 한 바퀴 기다림은 45초로 제한하고, 기한을 넘긴 종목은 직전 값과 지연 표시를 쓴다.

### 2. 같은 종목을 여러 번 적으면 중복 표시됨

- **현상**: `symbols_from` 은 앞뒤 공백 제거와 대문자 변환만 하고 중복을 지우지 않는다(`src/stockpulse.py:62-69`). 같은 종목이 두 번 조회되고, 사이드바 시세 슬롯도 두 칸을 쓴다.
- **개선안**: 순서를 유지하며 중복을 제거한다(`dict.fromkeys`).
- **범위**: `src/stockpulse.py` (`symbols_from`), `docs/usage.md`, `docs/usage.ko.md`
- **확인**: `symbols` 에 `AAPL` 과 `aapl` 을 함께 넣고 대시보드와 사이드바에 한 번만 나오는지 본다.
→ 완료: 종목 목록의 중복을 지운다 (대소문자·공백 무시, 처음 나온 순서 유지).

### 3. 비공식 Yahoo 엔드포인트에 의존하고, 오류 문구가 원문 그대로임

- **현상**: 시세는 Chrome 확장이 쓰는 Yahoo chart 엔드포인트를 직접 호출한다(`src/quotes.py:20`, 주석 `:96-97`). 공식 API 가 아니라서 응답 형식이나 접근 정책이 바뀌면 모든 종목이 같은 종류의 오류로 실패할 수 있다. 오류 문구는 Yahoo 가 준 `description` 을 그대로 보인다(`src/quotes.py:105`).
- **개선안**: 응답 형식 오류와 접근 차단을 구분해 안내하고, 대체 제공자 설정 방법을 오류 문구에 함께 보인다. 엔드포인트 주소는 이미 상수 한 곳에 있으므로 유지한다.
- **범위**: `src/quotes.py` (`fetch_yahoo`), `src/locales/*.json`, `docs/usage.md`
- **확인**: 응답 형식이 다른 가짜 응답으로 단위 테스트를 추가하는 방향을 검토한다(확인 필요).
→ 완료: 차단·형식 오류를 나눠 보이고, 토큰이 없으면 대체 안내를 보인다.
